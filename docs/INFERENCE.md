# Inference

Primary checkpoint: `Qwen/Qwen3-0.6B-GGUF`, `Qwen3-0.6B-Q8_0.gguf`. Revisions and hashes are recorded in `configs/runtime.lock.json`; model weights are excluded from Git. The pinned llama.cpp archive is downloaded and verified by `scripts/setup_runtime.py`. Runtime dependencies are C/C++ libraries bundled by that build; the client uses vendored cpp-httplib over local HTTP without TLS.

`LlamaServerBackend` checks `/health`, optionally reads `/props` for build/model/context metadata, and sends `/v1/chat/completions`. The generation body includes model alias `Qwen3-0.6B`, messages, seed, temperature, max_tokens, `chat_template_kwargs.enable_thinking=false`, and a `response_format` JSON schema. Responses are non-streaming. Native single `tool_calls` responses can also be normalized, although the baseline requests the explicit JSON action protocol. Multiple simultaneous tool calls are rejected.

The tool schema has one action branch per tool, plus a final-answer branch. An ordered schema serializer places the action type and tool name before arguments and required properties before optional ones. This matters because llama.cpp's grammar preserves schema property order: choosing arguments before the tool identity creates an avoidable ambiguity for a small model. Internal JSON remains canonical for repeated-call detection. Grammar constraints reduce malformed output; they do not establish that selected tools or arguments solve the task. The runtime repeats validation on every response. Invalid/truncated JSON and invalid arguments receive bounded corrective feedback. HTTP failures terminate with a backend error. Output size and request deadlines are bounded, redirects disabled, and only loopback hosts allowed.

Start the server with `python3 scripts/start_server.py`. This translates the validated configuration into startup flags and uses the template embedded in the GGUF with Jinja enabled. The agent does not set CPU threads/context/batch by sending unsupported chat-completion fields. It checks the reported server context size where available, but does not claim to verify every startup flag. Keep server and agent on the same configuration and restart before changing startup settings. The helper forces CPU execution and one slot.

Health/model aliases are not cryptographic identity checks. The setup helper verifies the official weight hash; an independently started server remains the user's responsibility. The checkpoint is never replaced with a larger model. Runtime manifests record the pinned source revision and actual binary hash, even when an archive-built server prints an unknown Git build identifier.

Token counts and server timing fields are copied when available. Missing usage is null, including scripted mode. Non-streaming HTTP observes total request latency; TTFT is not measured. Server model load time, process memory, and CPU utilization need separate instrumentation before optimization experiments. Input context is retained in full with a byte cap; tokenizer-specific token limits can still reject requests. Thinking mode is planned and rejected by the baseline configuration validator because it needs separate grammar/reasoning validation.

Primary references: [llama.cpp HTTP server](https://github.com/ggml-org/llama.cpp/blob/0ce8cd11416c8840498e6701bcbe39ad4b858c2b/tools/server/README.md), [official Qwen3 GGUF model card](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF/tree/23749fefcc72300e3a2ad315e1317431b06b590a).
